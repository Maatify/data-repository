## ADR-004 — SQL Identifier Quoting Consistency

**Status:** ✅ Accepted
**Date:** 2025-12-19
**Project:** `maatify/data-repository`
**Decision Owner:** Maatify Architecture

## 🧠 Context

`GenericMySQLRepository` and related MySQL repositories dynamically generate SQL queries using a configured table name (`$this->tableName`).

While insert and update operations correctly quote SQL identifiers, some read operations interpolate the table name directly into SQL statements without quoting. This leads to **inconsistent behavior** and potential runtime failures when:

* Table names collide with SQL reserved keywords (e.g. `order`, `group`)
* Database engines enforce strict SQL modes
* Cross-DB portability is required

Consistency in identifier quoting is mandatory for correctness and predictability.

---

## ❗ Problem Statement

Inconsistent identifier quoting causes:

* Queries that succeed on write but fail on read
* Hard-to-diagnose production errors
* Incompatibility with reserved identifiers
* Violation of the library’s safety guarantees

This inconsistency represents a **latent production bug**, not a stylistic issue.

---

## ✅ Decision

### 1️⃣ **Mandatory Identifier Quoting**

All SQL identifiers **must be quoted consistently** using the internal quoting mechanism.

This applies to:

* Table names
* Column names (when dynamically referenced)
* Aliases (if applicable)

No raw interpolation of identifiers is permitted.

---

### 2️⃣ **Scope of Enforcement**

The following operations **must** use quoted identifiers:

* `find`
* `findBy`
* `count`
* `paginate`
* `delete`
* `update`
* `insert`

There are **no exceptions**.

---

### 3️⃣ **Centralized Quoting Logic**

Identifier quoting must be:

* Centralized
* Reusable
* Database-aware (PDO / DBAL)

Repositories must not implement ad-hoc quoting.

---

### 4️⃣ **Backward Compatibility Preserved**

This change:

* Does not alter public APIs
* Does not affect parameter binding
* Only improves SQL correctness

No migration or consumer changes are required.

---

## 🔧 Mandatory Implementation Requirements

This ADR mandates:

1. Auditing all SQL-generating methods
2. Replacing direct table name interpolation
3. Enforcing quoted identifiers everywhere
4. Adding regression tests for reserved table names

---

## ❌ Explicitly Rejected Alternatives

The following are rejected:

* Leaving read queries unquoted
* Trusting user-defined table names
* Escaping identifiers via string manipulation
* Relying on database permissiveness

Identifier safety must be explicit and enforced.

---

## 🏁 Consequences

### Positive

* Eliminates reserved keyword failures
* Improves cross-database compatibility
* Prevents subtle production bugs
* Strengthens safety guarantees

### Trade-offs

* Slight increase in internal complexity
* Minimal refactor effort

These trade-offs are **acceptable and required**.

---

## 📌 Final Note

This ADR **locks SQL identifier quoting behavior** for `maatify/data-repository` v1.x.

All SQL generation must comply with this decision.
